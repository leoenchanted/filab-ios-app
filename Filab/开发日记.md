# Filab 开发日记

整理时间：2026-05-30

这份开发日记用来记录 Filab 这几天一起推进的功能进展。  
之后只有在你明确说“更新开发日记”时，才继续按当天日期追加，不自动更新。

## 2026-05-26

今天主要重新看了一遍项目，确认 Filab 的核心方向不是单纯套滤镜，而是一个围绕胶片影像的完整工作流。

完成的事：

- 梳理了 App 目前的主要功能：相册导入、胶片预设、照片调节、导出和本地记录。
- 明确后续会把相册、编辑器、设置、相机拆成更清楚的模块。
- 记录了一个重要原则：相机和新功能都要复用原来的胶片系统，不能另外做一套滤镜逻辑。

## 2026-05-27

今天重点处理照片调节里高光、阴影、白色、黑色太硬的问题。

完成的事：

- 优化了高光、阴影、白色、黑色的调节手感。
- 把这些调节从简单的数值加减，改成更柔和的亮度映射。
- 减少了死白、死黑和断层感。
- 后续又单独收紧了阴影和黑色的力度，让极值滑块不再一下子把画面推崩。
- 保持用户看到的滑块范围是 `-100...100`，但内部实际渲染力度仍然按受控范围执行。

今天的结论：

调光不能只看数值有没有变化，还要看画面有没有保住层次。暗部尤其要克制，因为用户对阴影变化会更敏感。

## 2026-05-28

今天主要做项目结构整理。

完成的事：

- 把项目按功能拆成更清楚的目录。
- `App/` 负责应用入口和整体页面。
- `Features/Library/` 负责相册导入和历史记录。
- `Features/Editor/` 负责胶片选择、调节、对比和导出。
- `Features/Camera/` 负责相机入口、取景器、拍照和保存。
- `Features/Settings/` 负责设置项。
- `Core/` 负责胶片模型、渲染、历史记录和全局状态。
- 更新了 `AGENT.md`，把项目规则、重要文件和后续开发要注意的地方写进去。

今天的结论：

后面 Filab 会继续变大，所以现在先把模块边界分清楚。这样以后加相机、胶片配方、相册管理、批量处理时不会全部堆在一个地方。

## 2026-05-29

今天开始把相机从“入口按钮”推进成真正的系统相机功能。

完成的事：

- 新增了底部右侧的独立相机入口。
- 调整了底部导航方向：左边是相册和设置，右边是独立相机按钮。
- 接入系统相机权限请求。
- 接入 AVFoundation 相机预览。
- 支持前后摄切换。
- 支持系统级变焦。
- 支持拍照后直接保存到系统相册。
- 支持 JPEG、HEIF 和 RAW 格式选择。
- 明确 RAW 就保存真正的 DNG 原始文件，不套胶片效果。
- 修复了 RAW 拍照崩溃问题，避免在 RAW 捕获时设置系统不支持的质量优先级。

今天的结论：

RAW 必须是真的 RAW。选择 RAW 以后，最终照片不应该烘焙胶片效果，只能保存原始 DNG，并且 UI 要给用户明确提示。

## 2026-05-30

今天主要围绕相机体验和 UI 继续调整。

完成的事：

- 继续调整底部相机入口，让它更接近 iOS 26 Liquid Glass 的独立主功能按钮。
- 避免出现两条 tabbar，只保留一个真正可见的底部入口。
- 把相机页面改成更接近专业胶片相机的布局。
- 取景器成为屏幕主体，控制项浮在画面周围。
- 顶部只保留格式和画幅这类核心选项。
- 加入 ISO、快门、EV、对焦、白平衡、电量等读数区域。
- 加入左侧工具栏，并按一页 5 个工具的方式整理，方便以后继续扩展。
- 加入直方图入口。
- 保留 1x 和 2x 快捷变焦，并支持手势继续缩放。
- 胶片选择改成两层结构：上面是品牌 / 分类，下面是具体胶片。
- 相机胶片预览直接复用现有胶片预设，不再单独维护一份相机胶片列表。
- 底部功能区开始承载 EV、快门、ISO、白平衡和胶片选择。
- 功能面板支持点击取景器空白区域收回。
- 快门按钮调整为更居中的结构。
- 照片 / 视频切换改为小框选中态，不再使用小圆点。

今天的结论：

相机 UI 不能只是“把功能放上去”，比例、间距、图标大小和层级都要像一个真正的拍摄工具。接下来还要继续按参考图慢慢收。

## 2026-05-31

今天主要处理相册入口、底部 TabView 和 RAW 格式语义。

完成的事：

- 暂停继续折腾自定义底部相机入口，把 App 底部导航退回系统原生 `TabView`。
- 底部只保留「相册」和「设置」两个原生 tab，避免自定义 TabBar 和系统 Liquid Glass 行为互相打架。
- 把相机入口移到相册页右下角，和原来的添加照片按钮组成一组悬浮按钮。
- 紫色相机按钮负责打开相机，橙色加号负责选择系统相册照片。
- 修复空相册状态下右下角悬浮按钮不显示的问题；现在无论有没有添加过照片，按钮组都会一直显示。
- 修复相册选择照片后导入顺序错位的问题，改用当前资源表示和选择 token，避免异步回调把后面的照片带进来。
- 重新查 Apple RAW / ProRAW 的差异，确认 Apple ProRAW 是计算摄影 RAW，可以保留 RAW 编辑空间并结合 Apple 多帧融合；普通 Bayer RAW 更接近传感器 RAW。
- 把相机格式从笼统的 `RAW` 拆成 `ProRAW` 和 `Bayer` 两个选项。
- 格式菜单会根据设备能力动态显示：支持 ProRAW 才显示 ProRAW，支持 Bayer RAW 才显示 Bayer。
- 相机 UI 增加 RAW 小提示：ProRAW 显示「多帧融合 RAW」，Bayer 显示「传感器 RAW」，不支持时显示「当前设备不支持」。
- RAW 拍摄逻辑不再使用 `availableRawPhotoPixelFormatTypes.first` 碰运气，而是显式选择 Apple ProRAW pixel format 或 Bayer RAW pixel format。
- RAW 保存提示会区分 `ProRAW DNG` 和 `Bayer DNG`。

今天的结论：

相机格式不能只写一个「RAW」。用户真正想要的是两种不同东西：一种是 Apple 计算摄影参与后的 ProRAW，一种是更原始的 Bayer RAW。UI 必须把这个差异说清楚，并且按设备能力显示，不能让不支持 ProRAW 的手机看到假选项。

## 2026-06-04

今天重点把相机胶片实时预览从 SwiftUI 近似效果推进到真正的 Metal 取景链路。

完成的事：

- 排查了把 SwiftUI `.colorEffect()` 直接套在 `AVCaptureVideoPreviewLayer` 上导致黑屏和卡顿的问题。
- 确认正确路线应该是 `AVCaptureVideoDataOutput` 拿实时帧，`CVMetalTextureCache` 包成 Metal texture，再由 `MTKView` 渲染。
- 新增 `MetalCameraPreviewView`，胶片模式取景器现在走 `MTKView`。
- 复用现有 `AVCaptureVideoDataOutput`，同一份 sampleBuffer 同时服务实时 Metal 预览和直方图，避免再加第二路 video output。
- 新增 `CameraPreviewFrameSource`，把最新 `CVPixelBuffer` 在线程安全的小容器里传给 Metal renderer。
- 在 `PreviewCore.metal` 里新增相机实时预览 shader，完成 `YUV -> RGB -> Linear -> 白平衡 -> 色彩矩阵 -> 曲线 LUT -> 0.18 中心对比度 -> 饱和度 -> Fade -> sRGB`。
- 把主曲线预生成 256 像素 1D LUT texture，避免每个像素循环曲线点，保证实时预览性能。
- 修复 `deliversPreviewSizedOutputBuffers` 的运行时断言，按要求先设置 `automaticallyConfiguresOutputBufferDimensions = false`。
- 修复 Metal 预览上下重影 / 扭曲问题：原因是 aspect-fill UV 裁切比例写反，导致边缘被 sampler clamp 拉伸。
- 拆分预览方向和拍照方向：实时取景器保持稳定构图，不跟着横竖屏旋转；照片输出继续用 `AVCaptureDevice.RotationCoordinator` 判断横竖屏。
- 清理 Swift 6 actor isolation warning，让当前构建保持 `errors: 0 / warnings: 0`。

今天的结论：

实时胶片预览可以走 Metal，而且这是正确方向；但入口不能是 SwiftUI `.colorEffect()` 叠系统 preview layer。预览和拍照也不能共用同一个旋转逻辑：取景器要稳定，照片方向要准确。

## 后续要守住的事情

- 胶片系统不要复制两套，相机和编辑器要尽量复用同一套胶片模型。
- ProRAW 和 Bayer RAW 要明确区分，不要再笼统写一个 RAW。
- RAW 类格式不要偷偷套滤镜。
- JPEG / HEIF 才可以把当前胶片效果烘焙进照片。
- 调光不能硬裁剪，要保留高光和暗部层次。
- 阴影和黑色调节要克制，不能把噪点和黑场硬拉起来。
- 相机 UI 要像专业工具，比例和层级比装饰更重要。
- Liquid Glass 尽量使用系统原生能力，不手写假玻璃效果。
- 大改项目结构、渲染逻辑、相机逻辑后，要同步更新 `AGENT.md`。
