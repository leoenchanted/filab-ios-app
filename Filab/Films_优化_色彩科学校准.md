# Filab 胶片预设 — 色彩科学校准与优化指令

> **给 Agent 的说明**：本文档基于大量真实胶片色彩科学研究，列出每支胶片的「真实色彩特性」及「当前预设的偏差问题」，以及「优化指令」。请逐项执行修正，所有数值修改请同步更新 `FilmPreset.swift`。

---

## 研究来源与方法论

所有色彩特性描述均来自：
- 各胶片官方技术数据手册（Kodak / Fujifilm / Ilford / CineStill）
- 专业实验室（The Darkroom, Richard Photo Lab, Blue Moon Camera）的大量冲洗测试分析
- 权威摄影评测站点（Casual Photophile, Analog.Cafe, Emulsive, Analog Wonderland）
- Imaging Resource 对 Fujifilm 胶片模拟的科学色彩图分析
- 色彩科学分析（Dehancer, Daydream Film 对各胶片的 LUT 分析）

## 一、Kodak Portra 400

### 真实色彩特性（研究确认）

- **色温倾向**：暖调，Kodak warm base 底层偏黄-橙，非中性
- **对比度**：中低对比，highlight 柔和压缩，shadow 有细节
- **饱和度**：中等自然，非鲜艳
- **皮肤色调**：全球最佳皮肤还原之一，轻微偏暖
- **色彩特点**：reds/yellows/oranges 强于 Fuji；greens/blues 不如 Fuji 鲜艳
- **shadow 行为**：阴影保留细节好，中性灰在阴影区有轻微暖偏
- **grain**：同等感光度中颗粒最细

### 当前预设评估

| 参数 | 当前值 | 评估 |
|---|---|---|
| WhiteBalance | temp=0.08, tint=0.015 | ✅ 方向正确，轻微偏暖 |
| ColorMatrix 蓝通道 | row3=[0.035, 0.055, 0.91] | ⚠️ B 通道 0.91 减蓝可以，但 G→B 串扰 0.055 过高，会让蓝色偏洋红 |
| ColorMatrix 红通道 | row1=[0.95, 0.035, 0.015] | ✅ 合理，R 轻微减但保留暖调串扰 |
| Tone Curve | [0,8],[48,55],[128,132],[210,225],[255,242] | ✅ toe 抬起(0→8)=胶片底雾，shoulder 压缩(210→225)=高光柔和，正确 |
| Saturation | 0.96 | ✅ 略低于中性，正确 |
| Contrast | 0.96 | ✅ 低对比，正确 |
| Grain | intensity=0.04, mode=spectral | ✅ 细颗粒正确 |

### 🔧 优化指令

```
问题 1：蓝通道 G→B 串扰(0.055)过高
原因：真实 Portra 蓝色区域是干净的蓝，不应有过多洋红偏移
修正：将 ColorMatrix row3 从 [0.035, 0.055, 0.91] 改为 [0.02, 0.03, 0.94]
     理由：减少 R→B 和 G→B 串扰，蓝通道更纯净；B 从 0.91 提到 0.94 略微还原蓝色

问题 2：Tint 方向微调
原因：真实 Portra 的洋红倾向非常轻微，0.015 已经合理
保持：tint=0.015 不变

问题 3：shadow 颜色特性缺失
原因：Portra 在阴影中有极轻微暖偏（研究记载"shadows retain warmth"）
建议：在 Adjust pass 的 splitShadowHue=30(偏橙), splitShadowSaturation=3（极轻微）
```

## 二、Kodak Gold 200

### 真实色彩特性（研究确认）

- **色温倾向**：强烈暖调，黄-橙 cast 是标志性特征
- **色彩行为**：
  - 蓝色：基本真实，但可能带轻微 cyan 偏移
  - 绿色：**偏黄绿**（yellow-green shift），这是 Gold 的标志
  - 黄色：强烈发光（glow intensely）
  - 红色：暖橙色调，皮肤显健康感
- **Shadow 特性**：阴影有轻微绿色偏移（区别于 Portra 的暖阴影）
- **对比度**：消费级，轻微偏向高对比
- **颗粒**：消费级，稍粗于 Portra
- **总体感觉**：复古怀旧，暖黄调，"vintage sunny"

### 当前预设评估

| 参数 | 当前值 | 评估 |
|---|---|---|
| WhiteBalance | temp=0.14, tint=0.02 | ✅ 强暖调，方向正确 |
| ColorMatrix row1（红） | [1.035, 0.025, -0.06] | ✅ 从蓝移除(−0.06)使红更暖，正确 |
| ColorMatrix row2（绿） | [0.055, 0.94, 0.005] | ⚠️ 绿通道 R→G 串扰 0.055 使绿色偏暖，正确方向，但 G 本体 0.94 偏低（绿色稍压），应略高 |
| ColorMatrix row3（蓝） | [0.015, 0.065, 0.92] | ⚠️ G→B 串扰 0.065 过高，Blue 会偏 cyan 但程度太强 |
| Saturation | 1.08 | ✅ 稍高，消费级鲜艳感 |
| Fade | 0.07 | ✅ 轻微褪色感，符合消费胶片 |

### 🔧 优化指令

```
问题 1：Green 通道的黄绿偏移需要调整
当前：row2=[0.055, 0.94, 0.005]，G 值 0.94 稍低使绿色略微发暗
修正：row2=[0.04, 0.97, -0.01]
     理由：G→G 提升至 0.97 保留绿色亮度；R→G 减少至 0.04（轻微暖化即可）；B→G 轻微负值(-0.01)移除蓝色从绿色中，使绿色偏黄绿

问题 2：Blue 通道 G→B 串扰过强
当前：row3=[0.015, 0.065, 0.92]，G→B=0.065 推蓝色偏 cyan 太强
修正：row3=[0.01, 0.04, 0.93]
     理由：轻微 cyan 倾向保留，但不过度

问题 3：Shadow 绿色偏移缺失
原因：Gold 在阴影/过曝时有明显绿色偏移（区别于 Portra）
建议：splitShadowHue=140（绿色区域）, splitShadowSaturation=5~8
     或在 Green Curve 上添加：[0,0],[128,132],[255,255]（略微提升绿色中间值）
```

## 三、Fuji Pro 400H

### 真实色彩特性（研究确认）

- **色温倾向**：冷调/中性，daylight 平衡但有轻微 cool 偏绿
- **色彩分裂**：**Shadow 冷（绿/青），Highlight 轻微暖（红）** — 这是 400H 的独特分裂色调
- **过曝特性**：过曝后绿色变成柔和粉彩（pastel green）
- **皮肤色调**：极佳，高光中皮肤非常自然
- **对比度**：低对比，宽容度极大（4-5 stops over exposure）
- **颗粒**：中等细腻，有粒感但不夸张
- **总体**：柔和、空气感、适合人像和婚礼

### 当前预设评估

| 参数 | 当前值 | 评估 |
|---|---|---|
| WhiteBalance | temp=-0.06, tint=-0.02 | ✅ 偏冷偏绿，正确 |
| ColorMatrix row1（红） | [0.90, 0.065, 0.035] | ✅ R 降至 0.90（红色略压），G→R 串扰 0.065 稍高 |
| Red Curve | [0,0],[128,122],[255,235] | ✅ 压缩高光红，有助于 shoulder 柔和 |
| Blue Curve | [0,22],[128,130],[255,245] | ✅ 提亮阴影蓝，增加 shadow 冷调 |
| Saturation | 0.94 | ✅ 略低，柔和感 |
| Contrast | 0.92 | ✅ 低对比，正确 |

### 🔧 优化指令

```
问题 1：缺少 Shadow 冷 + Highlight 暖的分裂色调（这是 400H 最重要特征）
原因：研究明确指出"cool color cast in shadows and a slight red color cast in highlights"
修正：在 Adjust pass 中配置 splitShadowHue=200（青蓝色），splitShadowSaturation=8
     splitHighlightHue=30（暖橙），splitHighlightSaturation=6
     splitBalance=-10（稍微偏向 shadow）

问题 2：ColorMatrix row1 的 G→R 串扰(0.065)偏高
原因：使红色区域稍带绿色调，看起来不够自然
修正：row1=[0.92, 0.045, 0.015]
     理由：R 稍提至 0.92（不要压太低），G→R 减少至 0.045

问题 3：过曝 pastel 特性无法在 preshot 预设中体现
说明：这是胶片物理特性，在数字模拟中属于曝光依赖行为
建议：通过 Fade=0.06（轻微提升）+ 在 B Curve 上加强 shadow 蓝色提升来模拟
     将 Blue Curve 改为 [0,28],[128,132],[255,245]（更强的 shadow 蓝提升）
```

## 四、Fuji Velvia 50

### 真实色彩特性（研究确认）

- **核心特征**：全球最高色彩饱和度的胶片，鲜艳度极致
- **对比度**：**高对比**（重要！），shadow 深黑，highlight 中性
- **色彩**：每种颜色都被增强，红色/橙色/黄色极其鲜艳
- **专用场景**：风光、自然摄影 —— 不适合人像（过于饱和）
- **颗粒**：极细（ISO 50 幻灯片），几乎无颗粒
- **白平衡**：中性，daylight 平衡

### 当前预设评估

| 参数 | 当前值 | 问题 |
|---|---|---|
| ColorMatrix | [1.1, -0.05, -0.05 / -0.05, 1.1, -0.05 / -0.05, -0.05, 1.1] | ✅ 对角线提升+交叉抑制，增强色彩分离，方向正确 |
| **Tone Curve** | **linear [0,0],[64,64],[128,128],[192,192],[255,255]** | ❌ **严重错误！Velvia 是高对比幻灯片，线性曲线完全错误** |
| Saturation | 1.38 | ✅ 高饱和度，正确 |
| Contrast | 1.1 | ⚠️ S 曲线对比合理，但线性 ToneCurve 已经是无对比，二者矛盾 |
| Fade | 0.0 | ✅ 幻灯片无底片雾，正确 |
| Grain | intensity=0.08 | ⚠️ Velvia ISO 50 是极细颗粒，0.08 偏高，应降至 0.03~0.04 |

### 🔧 优化指令

```
问题 1（严重）：Tone Curve 为线性，完全错误
原因：Velvia 50 是幻灯片（slide film），对比度极高，shadow 非常深，highlight 中性明亮
     线性曲线=无胶片特性，这是最大的偏差
修正：将 Tone Curve 改为：
     [0,0], [40,22], [100,90], [160,175], [220,240], [255,255]
     说明：shadow 大幅压深(40→22)，mid-shadow 稍压(100→90)，mid-highlight 提升(160→175)，
           高光保持干净(220→240)，这才是真实的幻灯片 S 型曲线

问题 2：Grain 强度过高
修正：grain intensity=0.03, softness=0.7（ISO 50 幻灯片几乎无颗粒）

问题 3：ColorMatrix 对红色和蓝色的提升应更明显
原因：Velvia 以红色和蓝色极致鲜艳著称（风光里天空/草地/日落极致）
修正：row1=[1.15, -0.06, -0.06]（红通道提升）
     row3=[-0.06, -0.06, 1.15]（蓝通道提升，保持 cyan 比例）
     row2=[-0.05, 1.08, -0.05]（绿通道略低，避免太绿）

问题 4：Contrast 参数与 ToneCurve 重复
说明：修正 ToneCurve 后，Contrast 值应调整为 1.0（曲线已提供对比度）
```

## 五、CineStill 800T

### 真实色彩特性（研究确认）

- **最核心特征**：**钨丝灯平衡（3200K）**，在日光下产生强烈青蓝色调
- **Halation**：去除 remjet 层后，强光源周围产生红色光晕 —— 这是标志性特征
- **钨丝灯下**：颜色准确，橙黄色调自然，皮肤温暖
- **日光下**：强 teal-blue cast（除非加 85B 滤镜）
- **色彩**：在夜晚都市场景中，红色略微过饱和；Neon 灯颜色极为电影感
- **颗粒**：中等，有电影感质感（chromatic grain）
- **对比度**：中等，shadow 有控制

### 当前预设评估

| 参数 | 当前值 | 评估 |
|---|---|---|
| WhiteBalance | temp=-0.18, tint=-0.02 | ✅ 强冷调，正确（钨丝灯平衡） |
| ColorMatrix row3（蓝） | [0.08, 0.12, 0.80] | ⚠️ B 通道大幅减弱(0.80)，R/G 串扰提高，创造 teal 感，但串扰比例需要检查 |
| Halation | strength=0.6, colorShift=[1.8,0.4,0.1] | ✅ 强红色光晕，完全正确 |
| Grain | chromatic(2), colorVariance=0.3 | ✅ 彩色颗粒，符合 CineStill 特性 |
| Vignette | 0.14 | ✅ 夜间/室内暗角感，合理 |

### 🔧 优化指令

```
问题 1：ColorMatrix 蓝通道的 teal 方向需验证
分析：蓝色通道 row3=[0.08, 0.12, 0.80]
     B 输出 = 0.08*R + 0.12*G + 0.80*B
     这会使蓝色中含有更多红绿成分，实际上产生的是 desaturated/shifted 蓝色
     真实 800T 在日光下产生的是 teal（青蓝）cast
修正：row3=[0.05, 0.15, 0.78]
     理由：增加 G 串扰至 0.15 使蓝色向 cyan 倾斜，减少 R 串扰（红串入蓝不对）
           B 本体稍微再压低至 0.78 加强冷调

问题 2：Tone Curve 的 shadow 特性
当前：[0,0],[52,38],[135,148],[205,228],[255,245]
分析：shadow 大幅压深(52→38)，highlight 较大提升(205→228)，整体高对比
研究说明 800T 是"natural contrast and well-controlled"，shadow 不应过于死黑
建议：将 [52,38] 改为 [52,42]，略微还原一点 shadow 细节

问题 3：Saturation 0.95 偏低
分析：CineStill 800T 在钨丝灯下颜色是准确的（非去饱），特别是红色在夜景中会过饱和
建议：Saturation=1.0（保持中性），让 ColorMatrix 和 WB 完成色彩塑形
```

## 六、CineStill 50D

### 真实色彩特性（研究确认）

- **平衡**：日光平衡（5500K），daylight 下颜色准确、动态
- **颗粒**：极细（声称世界最细颗粒 C-41 胶片）
- **色彩**：真实、动态、略有 pastel 倾向，皮肤色调极佳（研究：比 Portra 更好）
- **扫描特性**：扫描后有轻微黄绿偏移，通常需要轻微色彩校正
- **Halation**：存在但弱于 800T（日光场景中高对比边缘）
- **曝光宽容度**：宽泛，建议轻微过曝

### 当前预设评估

| 参数 | 当前值 | 评估 |
|---|---|---|
| WhiteBalance | temp=0, tint=0（中性） | ⚠️ 研究记录"扫描后有轻微黄绿cast"，应模拟这个特性 |
| ColorMatrix | [0.95,0.03,0.02 / 0.02,0.96,0.02 / 0.03,0.08,0.89] | ⚠️ 基本中性，但 G→B 串扰 0.08 较高，会使蓝色偏 cyan 过多 |
| Halation | colorShift=[1.2,0.9,0.7] | ⚠️ 50D 的 halation 接近中性橙而非强红，但 1.2/0.9/0.7 这个比例还是偏红，可接受 |
| Grain | 同 Portra（intensity=0.04） | ✅ 细颗粒合理 |

### 🔧 优化指令

```
问题 1：缺失扫描黄绿偏移特性
研究依据：多个评测记录"scans yellow and sometimes green"
修正：WhiteBalance temp=+0.02, tint=-0.015（极轻微暖+轻微偏绿）
     说明：这是模拟真实扫描特性，不是色彩"错误"

问题 2：ColorMatrix 蓝通道 G→B 串扰偏高
当前：row3=[0.03, 0.08, 0.89]，G→B=0.08 使蓝色偏 cyan
修正：row3=[0.02, 0.04, 0.93]
     理由：50D 在日光下颜色应更中性准确，不需要强 cyan 偏移

问题 3：Halation colorShift 更接近中性
研究记录：50D halation 比 800T 温和得多，颜色更接近"subtle warm" 而非纯红
修正：colorShift=[1.15, 0.85, 0.75]（稍微更中性的暖橙色光晕）
```

## 七、Ilford HP5 Plus（黑白）

### 真实色彩特性（研究确认）

- **色调响应**：中低对比，BT.709 亮度权重（0.2126 R + 0.7152 G + 0.0722 B 更精确，但 0.30/0.59/0.11 也可接受）
- **亮度范围**：shadow 保留细节优秀（「比很多同类胶片保留更多 shadow 细节」）
- **高光**：极好的高光宽容度，几乎不会溢出
- **颗粒**：传统颗粒（cubic grain），有质感但不粗糙
- **特点**：mid-tone 丰富，整体「有雕刻感」

### 当前预设评估

| 参数 | 当前值 | 评估 |
|---|---|---|
| 亮度矩阵 | [0.3, 0.59, 0.11] | ✅ 接近 Rec.601，适合黑白胶片 |
| **Tone Curve** | **[0,0],[50,35],[128,138],[195,230],[255,255]** | ⚠️ [50,35] 阴影压太深，HP5 的 shadow 细节保留优秀 |
| Contrast | 1.08 | ✅ 轻微提升，合理 |
| Grain | intensity=0.15, softness=0.45 | ⚠️ 0.15 稍高，HP5 颗粒适中，0.12 更准确 |

### 🔧 优化指令

```
问题 1（重要）：Tone Curve shadow 过暗
研究依据：HP5 "retains more shadow detail than many comparable films"
当前 [50,35] 意味着 50/255 输入被压到 35/255，shadow 损失约 15/255
修正：[0,0],[50,42],[128,136],[195,228],[255,255]
     说明：50→42 保留更多 shadow 细节，128→136 轻微提升中灰，195→228 高光拉伸

问题 2：Grain 强度略高
修正：intensity=0.12, softness=0.5（稍微柔化颗粒，softness 增加）

问题 3：亮度矩阵精确度
当前：[0.3, 0.59, 0.11]（Rec.601 近似值）
建议：改为 BT.709 精确值 [0.2126, 0.7152, 0.0722]
     原因：HP5 是全色敏感型（panchromatic）胶片，红色灵敏度较 Rec.601 偏低
           BT.709 的红色权重(0.2126)比 Rec.601(0.299)更符合现代全色胶片的光谱响应
```

## 八、Ilford Delta 3200（黑白）

### 真实色彩特性（研究确认）

- **真实感光度**：约 ISO 1000~1250（标注 3200 实际是在额定 push 状态）
- **颗粒**：T-grain 结构，35mm 中粗而有质感，120 格式细很多
- **对比度**：中等（非极高），低于 Kodak T-Max 3200
- **阴影**：在 ISO 3200 下 shadow 细节有限，建议轻微过曝或拉低 EI
- **高光**：平滑过渡，良好的高光宽容度

### 当前预设评估

| 参数 | 当前值 | 评估 |
|---|---|---|
| Tone Curve | [0,5],[50,40],[128,135],[200,225],[255,250] | ⚠️ shadow 区(50→40)稍暗，符合被推 push 后的感觉，但[0,5]的轻微底雾不准确（B&W 无底雾） |
| Contrast | 1.15 | ✅ 稍高对比，push 状态下合理 |
| Grain | intensity=0.25, softness=0.3 | ✅ 高颗粒、硬质颗粒，符合 Delta 3200 |
| Fade | 0.05 | ⚠️ B&W 胶片无 Fade（底色是黑不是橙），应为 0 |

### 🔧 优化指令

```
问题 1：Tone Curve [0,5] 引入底雾错误
原因：Fade/底色提升是彩色负片的特性（橙色 base），B&W 胶片没有这个现象
修正：将 [0,5] 改为 [0,0]（纯黑起始）

问题 2：Fade=0.05 不应存在于 B&W 预设
修正：Fade=0.0

问题 3：颗粒模式优化
当前：mode=spectral(1)
说明：Delta 3200 的 T-grain 结构与传统 cubic grain 不同，呈现更均匀的颗粒图案
建议：维持 spectral(1)，但可考虑测试更高的 fineSoftness（约 0.26）来模拟 T-grain 的平滑边缘
     具体：fineSoftness=0.26, fineWeight=0.50, coarseWeight=0.15（比标准 ilford grain 更细腻）
```

- **褪色感**：强烈，Fade 是标志性特征
- **对比度**：低，柔和
- **颗粒**：大而不均匀，chromatic（彩色颗粒）
- **Bloom**：Polaroid 有独特的柔光/边缘扩散感
- **饱和度**：低，有"复古照片"感

### 当前预设评估

| 参数 | 当前值 | 评估 |
|---|---|---|
| Fade | 0.16 | ✅ 强褪色，正确 |
| Blue Curve | [0,0],[255,215] | ✅ 全范围压低蓝色，正确 |
| Bloom | sigma=28, strength=0.55 | ✅ 强柔光，正确 |
| Grain | chromatic(2), colorVariance=0.35 | ✅ 彩色不均匀颗粒，正确 |
| ColorMatrix | [1.05,0.05,0.00 / 0.00,0.95,0.05 / 0.05,0.10,0.85] | ✅ 红提升、蓝大幅压低、G→B 串扰，正确 |

### 🔧 优化指令

```
问题 1：ColorMatrix 蓝通道 R→B 串扰(0.05)使蓝色含红
原因：真实 Polaroid 的蓝色是偏紫/洋红（因为蓝层弱），不是偏暖红
修正：row3=[0.02, 0.12, 0.85]
     理由：增加 G→B 串扰(0.12)使蓝偏 cyan/绿，减少 R→B(0.02)

问题 2：Tone Curve 的 shadow lift 过强
当前：[0,38] 使最深的黑变成 38/255，即使对于 Polaroid 也过于褪色
结合 Fade=0.16，双重提亮 shadow 可能过多
建议：将 [0,38] 改为 [0,28]，让 Fade 参数承担更多褪色工作

问题 3：WhiteBalance tint=0.1 过强
研究：Polaroid 的粉红/洋红偏移很有限
建议：tint=0.05
```

## 十、Kodachrome

### 真实色彩特性（研究确认）

- **最标志性特征**：
  - **红色**：富有深度的红，非常「special」，是 Kodachrome 的标志
  - **蓝色**：深邃，**略偏 cyan**（而非暖蓝或紫蓝）—— 这是关键！
  - **绿色**：鲜艳，带轻微黄绿偏移
- **对比度**：中等到较高，shadow 倾向较深黑
- **饱和度**：高但不「数字化」，色彩有深度感
- **颗粒**：极细（K-14 工艺的薄乳剂层）
- **色温**：轻微偏暖（黄色调），偏中性

### 当前预设评估

| 参数 | 当前值 | 评估 |
|---|---|---|
| **ColorMatrix 蓝通道** | **row3=[0.02, -0.05, 1.03]** | ❌ **严重错误！G→B 为 -0.05 使蓝偏紫，Kodachrome 蓝色应偏 cyan（G→B 应为正值）** |
| ColorMatrix 红通道 | row1=[1.05, -0.02, -0.03] | ✅ 红色提升，移除 G/B 串扰使红色更纯，正确 |
| ColorMatrix 绿通道 | row2=[-0.05, 1.08, -0.03] | ✅ 绿色提升，R→G 略有负值使绿更纯 |
| Tone Curve | [0,2],[64,58],[128,132],[200,225],[255,248] | ✅ shadow 较深(64→58)，高光轻微拉伸，有 Kodachrome 的冲击感 |
| Saturation | 1.15 | ✅ 合理 |

### 🔧 优化指令

```
问题 1（严重）：蓝通道 G→B 串扰方向错误
当前：row3=[0.02, -0.05, 1.03]，G→B=-0.05 将蓝色推向紫/洋红
正确应该：Kodachrome 的蓝色是 "slightly cyan-shifted" ≠ 偏紫
修正：row3=[-0.02, +0.06, 0.95]
     理由：G→B=+0.06 将蓝色推向 cyan（增加绿色成分）
           B 本体稍微压低(0.95)使蓝色更深
           R→B=-0.02 避免红串入蓝

问题 2：红色提升不够充分
当前：row1=[1.05,-0.02,-0.03]，R 提升 1.05 偏保守
研究："the reds, in particular, are legendary. They are deep, rich..."
修正：row1=[1.10, -0.04, -0.04]
     理由：Red 通道提至 1.10，同时增大 G/B 的负串扰使红更「纯」

问题 3：Shadow 需要更深
研究："shadows tended to go to pitch black fairly quickly"
修正：Tone Curve [0,2] → [0,0]（shadow 完全到黑），[64,58] → [64,52]（更深 shadow）
     新曲线：[0,0],[64,52],[128,132],[200,225],[255,248]
```
